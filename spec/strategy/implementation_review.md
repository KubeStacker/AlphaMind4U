## 1. 已确认的正确性问题

### IR-01 / P1：S0用当天收盘信息决定当天开盘成交

[s0.go](../../services/quant-backend/internal/strategy/s0.go#L112)先更新当天收盘估值，
第143行用当天收盘判断止损，第155行按同一天开盘卖出；第199行建仓止损也使用当日收盘。
复现：已持仓、开盘10元、收盘8元，模型按此前10元开盘完成退出，最终净值499,807.83元。
应冻结上一决策时点意图，次日执行；单独分开收盘信息、执行价格和估值，补前缀不变性测试。
S0还会同一开盘复用卖出释放的名额/现金，并对取消单再次尝试；须按execution.md限制重试原因。

### IR-02 / P1：复权特征价格直接用于真实股数和现金账本

[market_store.go](../../services/quant-backend/internal/strategy/market_store.go#L33)归一到区间末因子，
[task_strategy.go](../../services/quant-backend/internal/engine/task_strategy.go#L92)再将其用作S0执行报价；S1同用Bar。
复现：增加后一天拆股记录后，同一历史日的输入开盘从20元变成10元。
这会改变可买股数、交易单位和费用；不能因为复权收益比例平滑，就当作真实账户回放。
应分离信号日尺度的特征与原始成交价，显式处理公司行动、现金权益、股数及退出线换算。

### IR-03 / P1：冻结数量在执行时未重新校验风险和额度

[s1s2.go](../../services/quant-backend/internal/strategy/s1s2.go#L324)按信号收盘定股数，
第236行执行仅核现金，不按实际参考买价与冻结退出线缩量，也未扣除保留现金和预留费用。
默认账户复现：16,900股，成交11.8118元，初始退出11.4829元，含买入佣金风险5,618.72元。
该数已经超过5,000元，尚未计退出费用；TotalRisk字段亦未接入组合计算。
应逐笔按实际价格、费用、单股/组合风险和金额上限取更严约束，只缩减冻结数量。

### IR-04 / P1：T+1被误用为禁止买入日生成次日卖出意图

[s1s2.go](../../services/quant-backend/internal/strategy/s1s2.go#L278)直接跳过当日新仓的全部退出检查。
复现：买入当天收盘已经跌破退出线，下一交易日结束仍持有，卖出被额外推迟一天。
应限制当日可卖量，允许买入日收盘形成下一交易日的止损、数据风险或账户退出意图。

### IR-05 / P1：受阻卖单会随收盘恢复而丢失

[s1s2.go](../../services/quant-backend/internal/strategy/s1s2.go#L194)跳过停牌/端点卖单后，
第211行清空全部待卖单；晚间只根据新条件重建，没有保留原退出理由。
复现：止损卖单在端点被阻，收盘反弹后，下一可执行日仍不卖出。
应持续保留未成交数量和原退出理由，成交后才清理；恢复趋势不能自动撤销全平意图。

### IR-06 / P1：账户停用可以绕过涨跌停成交限制

[s1s2.go](../../services/quant-backend/internal/strategy/s1s2.go#L201)对ExitHalt豁免端点检查。
复现：账户已停用且明确标记端点不可成交，持仓仍被全部变成现金。
停用只提高退出优先级，不能提高可成交性；仍须保留受困敞口、估值和下一次待卖单。

### IR-07 / P1：仓位上限下降未产生减仓，回撤规则也不完整

[s1s2.go](../../services/quant-backend/internal/strategy/s1s2.go#L295)仅以capNow==0触发整仓退出。
复现：市场允许上限从80%降到20%，经过下一开盘后实际仓位仍40.03%。
10%回撤仅限制新买；15%禁新增被混为全平；10%/15%严重状态未按规定锁定和解除。
[portfolio.go](../../services/quant-backend/internal/strategy/portfolio.go#L90)还硬编码10/15/20%，未消费账户阈值。
应分离允许持仓、是否新增、减仓数量和持久风险状态，并在每次执行后复核。

### IR-08 / P1：快照既不可保留修订版本，也不能正确覆盖缩短名单

[pool_store.go](../../services/quant-backend/internal/strategy/pool_store.go#L22)按月份覆盖头，
明细只Upsert现有名次；头/明细没有作为一个快照事务提交，也没有不可变版本键。
复现：同月从2条改为1条，读取v2仍返回2条，含旧版本残留股票。
数据版本固定为daily_price@latest，重复运行不能证明读到了同一数据版本。
应追加不可变版本、原子发布头和完整明细；修订后旧run仍绑定原版本，不只补一次删除尾行。

### IR-09 / P1：HTTP回放没有接入交易资格和涨跌停数据

[task_strategy.go](../../services/quant-backend/internal/engine/task_strategy.go#L75)未填Quals、Suspend、LimitDay，
S0报价也只填Open/Close；缺少资格记录会默认允许，端点默认false。
因此库内有日线的历史ST、无权限或开盘涨跌停证券，仍可能产生假定成交。
还缺历史最小申报量/递增量、合法价位、费用版本和行业/相关性50%上限；不能作为可执行基准。
应先完成G0规则来源与可用区间；未知资格或必要规则缺失应阻断相应绩效验收。

### IR-10 / P1：预热和交易日来源使无交易结果难以解释

[task_strategy.go](../../services/quant-backend/internal/engine/task_strategy.go#L63)仅加载from至to，
[s1s2.go](../../services/quant-backend/internal/strategy/s1s2.go#L418)却从同一Dates索引取60日窗口。
即使库内有起点前历史，起始59个记录日仍无法形成趋势信号；页面默认区间不足60点，必然无S1入场。
Dates取池内行情日期并集，不能发现全市场共同缺失日；未配置的生效月还会直接变成空池。
应分离预热区间和账户计息区间，按正式日历推进，检查月池覆盖及缺失原因。
