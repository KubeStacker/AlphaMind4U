## 1. 数据优先级

| 优先级 | 数据 | 当前基础 | 必须补齐或核验 |
|---|---|---|---|
| P0 | 全 A 股日线、成交额、复权因子 | daily_price | 历史全市场覆盖、去重、单位、缺失；包括退市证券 |
| P0 | 证券主表与交易日历 | stock_basic、trade_calendar | 历史上市状态、北交所覆盖、代码变更；拒绝以工作日冒充交易日 |
| P0 | 涨跌停价与历史交易资格 | suspend、namechange 部分可用 | 接入真实涨跌停价、历史 ST 与退市整理状态、规则版本 |
| P0 | 指数基准 | market_index 已采沪深300等 | 连续历史与发布时点；基准收益口径明确 |
| P1 | 波动、趋势、市场宽度 | 可由上述行情派生 | 指标预热、分母、有效样本与计算版本 |
| P1 | 行业归属 | stock_index_member_all | 当前采集取最新并替换，需历史有效区间或可靠历史来源 |
| P1 | 涨跌停、炸板、连板 | 尚无专表与任务 | 来源覆盖、板块适用性、发布时间和历史范围 |
| P2 | 资金流、两融、换手 | moneyflow、margin、daily_basic | 历史发布延迟、口径变化、单位及适用标的覆盖 |
| P3 | 财务、预告、公告与新闻 | 财报与事件表部分存在 | 历史版本、真实发布时间、来源证据，完成后再用于信号 |

行情成交额与资金流金额可能采用不同单位，归一化后才可计算资金流占成交额比例。
现有 `moneyflow` 官方口径为沪深 A 股，不能假设覆盖全部北交所证券；缺失不得当零。
源说明见 [Tushare moneyflow](https://tushare.pro/document/2?doc_id=170)。
涨跌停价源见 [stk_limit](https://tushare.pro/document/2?doc_id=183)，单次返回上限需分页核验。
两融周五部分数据可能周一才发布，见 [margin_detail](https://tushare.pro/document/2?doc_id=59)。

## 3. 时间、版本与缺失

- 分开保存业务日期、公开时间、系统采集时间、计算时间、策略可用时间及数据版本。
- 实际模拟使用系统已采集版本；历史研究若只有可靠公开时间，明确使用公开可得性代理假设。
- 无发布时间或无法还原旧版本的资料，不用于严格时点信号；不得补一个早日期来制造可用性。
- 首版信号允许仅用量价和指数运行S1/S2；成交账本仍必需交易状态、公司行动与历史费用。
- 实施后产生的修订追加记录；保留原推荐所用快照，后来的修订不覆盖历史决策证据。
- 缺失标记至少区分未发布、无交易、无权限、额度延期、失败和不适用。
- 分批入库不能暴露为完整日快照；特征与信号只消费已发布且通过质量门槛的数据版本。

## 4. 计算与存储边界

- 2026-09-08确认以[daily_batch.md](daily_batch.md)的日批提前计算为主，结果查询不触发任何策略重算。
- quant-backend 内规划 universe、feature、signal、portfolio、backtest 等职责包。
- 保留量化域唯一进程访问量化库的约束；MCP 和前端通过后端 HTTP 读取受控结果。
- 月度成交额与每日宽度按日期分批聚合，保存小型结果，避免每次推荐扫描全库。
- 公共特征按版本复用，证券层包括池内、旧仓和未完成退出；账户现金/股数独立核算。
- 个股长序列查询与全市场截面查询分别评估索引，新增 SQL 附 EXPLAIN 和耗时基线。
- 回测异步执行、限制并发与内存，具备取消和进度，不占据同步 HTTP 请求长时间计算。
- 日批与必要ETL优先于长研究任务；增量/全量等价、失效缓存与资源验收见[compute_quality.md](compute_quality.md)。
- 外部研究工具若需数据，只能使用后端受控导出并记录版本，禁止直接连接量化库文件。
- 不因股票池仅 20 只而只采 20 只：月度排名与市场宽度仍依赖全市场数据。

规划的数据对象：月度排名快照、每日特征快照、策略版本、运行记录、推荐意图、模拟成交和净值。
未来运行记录还包括参数/规则/费用版本、因子可用时间、拒单原因与监控结果，见 evolution.md。
旧strategy_pool_month/entry保留历史；0003追加月池和0004研究任务已部署，原始来源历史版本链仍待完成。
继续实施时先补迁移、字段语义及shared/contracts契约，不恢复旧策略表作为兼容包袱。

## 5. 数据验收门槛

- 原始月度排名可由后端用同一快照独立重算，名次、金额、时间边界一致。
- 核心字段缺失或重复导致名次、指标、成交不确定时，阻断相应信号并报告影响范围。
- 随机抽查、月末边界和已知异常日都与源数据对账；记录检查样本与差异处置。
- 交易日历范围完整；未覆盖区间明确失败，不以周一至周五自动补齐。
- 通过 restart、重试、数据延迟与任务部分失败场景后，才标记数据链路可用于模拟。
- 核心窗口需连续完整；行业与市场宽度分别核验预期分母，不能直接复用运营看板比例阈值。
- 源接口新增字段不等于当前库已保存；例如 daily_basic 的 limit_status 不在现役schema/采集列中。

## 6. 公司行动数据入口

- stock_dividend沿用现有表，显式采集基准日及基准股本；缺失仍保留缺失，不用零填充。
- 来源cash_div为每股税后分红、cash_div_tax为每股税前分红；名称不能用来猜测税费口径。
- stk_div为每股送转，stk_bo_rate/stk_co_rate分别为送股/转增比例；不能将三者相加重复计股。
- base_share单位为万股；这些字段定义见[Tushare dividend](https://tushare.pro/document/2?doc_id=103)。
- 采集失败和疑似截断必须显式返回，具体规则见[ETL规范](../backend/quant/etl.md#4-分红采集完整性)。
- 入账前仍需核验实施状态、登记/除权/派息/上市日期、版本可用时间以及持仓对应税费规则。
- 登记后已卖出的持仓也可能有待收权益；待收现金不等于可买入现金，未上市红股不可提前卖出。
- 本轮仅修复数据入口，不把来源税后字段当所有账户的实际到账金额，不解除因子变化阻断。

## 7. 起点前预热

S12回放先按参数最长窗口读取开始日前的正式交易日，最多向前查询366个自然日，缺预热日历则阻断。
行情和指数从实际所需预热首日加载；账户从用户开始日以C0/空仓运行，预热期不形成订单或绩效。
历史窗口仍按正式日历要求连续，个股上市不足或停牌缺行不能用更早行情凑够条数。
S0月中开始的月度窗口、来源历史版本和全市场证券覆盖仍另行验收，不因预热加载完成而关闭G0。

S0从开始月份首个自然日读取日历，开始日前只推进月度索引，避免月中起投重新开启月初建仓窗口。
股票/指数加载以LIMIT多取一行检测截断；请求证券完全无行情时报错，不能悄悄删掉池内股票。
缺少某一交易日仍须另做停牌/缺失归因，完整性检查尚不等于全市场G0认证。

当前行情采集在写入前要求同日有效复权，来源失败或不完整不覆盖旧数据；历史NULL仍需回补。
