# evolution — 从可复算基线到可持续运行的演进

> 历史参考：当前方案与待办已合并至[策略研究与实施方案](plan.md)。下文保留原日期记录；“方案被替代”不代表功能已验收。

> v0.4。演进由证据触发；Top20与最多两只保持，默认50万元，其他本金/额度情景分别验证。
> 2026-09-07实施状态：待实施，尚无模拟接管/监测/回退证据；不可归档，见[status.md](status.md)。

## 1. 演进原则

先提高数据和执行可信度，再提高选股与择时能力，之后才增加复杂度。
日常运行采用[daily_batch.md](daily_batch.md)：每日提前算好并发布，读取和解释不触发在线策略计算。
实际账户始终只有一个生效策略版本，所有版本合计最多两只；研究组合各自模拟，不共用真实资金。
现有主版本与候选版本在同一未来区间平行记录，候选不因短期收益领先而自动接管。
收益目标与风险约束冲突时报告证据；加杠杆、扩股票池、提高持仓数不是本方案的演进路径。
任何版本均可能停在研究阶段或被淘汰，没有必须最终采用复杂模型的要求。

## 2. 阶段、证据和下一步

| 阶段 | 增加什么能力 | 升级证据 | 不通过时怎么办 |
|---|---|---|---|
| V0 可信底座 | 历史池、发布快照、法定费用、交易规则、两只账本 | 名单可复算，关键执行样例和现金对账通过 | 只修数据/账本，不评价alpha |
| V1 简单策略 | S0/S1/S2及F1，机会漏斗、风险预算 | 多阶段有效样本、成本后收益与回撤证据 | 区分无机会、执行差和无预测力 |
| V2 入场与选择 | E2回踩、E1行业、E3失败突破各自对照 | 共同区间有稳定增量，满足factor_validation门槛 | 无效增强退出；保留已通过基础版 |
| V3 情绪和拥挤 | S3、换手分位、强股溢价、资金流诊断 | 口径及发布时间可靠，新增因子不只是复制价格 | 样本短继续积累，不回填不存在的历史 |
| V4 机构研究增强 | 财报历史版本、预期差、景气事件 | 公告前后时点可还原，行业内存在独立贡献 | 只保留研究解释，不驱动订单 |
| V5 长期运行 | 监控、候选对照、版本接管、执行校准 | 持续数据和执行达标，改变均可审计及回退 | 触发保护、复核或降级，保留所有轨迹 |

这些是能力阶段，不是必须严格串行的工期：V1通过即可先模拟，V2/V3在研究分支验证。
影子推荐、版本记录与风险监控从V1开始建设；V5是持续成熟，不是最后才开始监控。
残差动量、波动调整排序可在V2之后第二轮登记，不抢占价格基线和行业历史治理。
原始/复权账本与两只限制的缺陷始终是P0，不因已进入较高阶段而降低优先级。

具体改善提案、对照指标和工作闭环见 [improvement.md](improvement.md)。

## 3. 从失败归因决定怎么演进

| 观察到的问题 | 优先诊断 | 可演进方向 |
|---|---|---|
| 候选很多但股数为0或资金利用率低 | 最小交易量、ATR距离、重复风控上限 | 检验入场结构是否改善；仍受限则承认目标/风险冲突 |
| 突破经常失败，回落后再上涨 | 入场后不利波动、成交额分布、每周评估遗漏 | 比较每日评估与回踩分支，不把两项同时改掉 |
| 牛市收益强、市场转弱损失集中 | 指数风格偏差、全市场宽度、降仓延迟 | 单独验证市场/情绪覆盖，不事后挑牛市 |
| 两只经常同时大跌 | 行业、收益相关、共同事件和跳空 | 改善集中度诊断和执行压力模型，不视“两只”为分散 |
| 因子IC正但账户亏损 | 排名前两名效果、费用、拒单、持有期不匹配 | 优先修正策略转化和执行，不盲目加因子 |
| 财报“利好”无效果 | 发布时间、同比基数、是否早已预期、历史覆盖 | 补预期和事件证据，未补齐前停止该增强 |
| 模拟收益低于回测 | 延迟、真实追价、成交假设、数据修订 | 校准费用和成交模型，旧回测标记失配 |

所有改动先写假设和反例；“最近亏了所以调参数”不是充分升级理由。
如需时间止损、固定止盈或加仓，单独登记对照，不能悄悄开启v0.3关闭的开关。

## 4. 版本生命周期与接管

`草案 → 冻结研究 → 历史验证 → 影子推荐 → 有条件采用 → 监测 / 退役`

1. 草案阶段登记改动、数据依赖、实验预算与失败标准，不修改当前生效版本。
2. 冻结研究保存完整快照与配置摘要；实现、修正数据或修改费用均产生新run。
3. 历史验证采用共同时间段和成本压力；证据不足标记不足，不伪装通过。
4. 影子推荐与当前版本平行，至少20交易日检查运行；收益证据仍使用更长历史及持续记录。
5. 升级需要研究、数据、执行三类证据齐备和明确采用记录；不是系统按近期收益自动选择。
6. 新版只接管切换时间之后的新意图；旧持仓保留来源版本及原退出线，受更严格账户风控约束。
7. 过渡期间旧仓也占两只名额，不为新版另开两个仓；同一证券不给出互相抵消的重复意图。
8. 回退时撤销未执行的新买，生成必要风险意图；已有交易不能撤回，不重写历史净值。

没有任何已通过的可用版本时，默认禁止新增并处理存量风险；不自动回退到无风控策略。
数据缺失触发的是保护状态，不能把临时换成另一策略的轨迹仍记为原版结果。
本计划没有实盘下单授权；未来采用方式取决于模拟证据和账户约束完善情况。

## 5. 日常监测与复核触发

| 监测频率 | 指标/初始触发 | 动作 |
|---|---|---|
| 每个批次决策点 | 核心数据未通过质量、法定规则缺段、价格尺度不一致 | 禁止新增；标明影响范围与待退出 |
| 每个回填/重演事件 | 现金为负、实际持仓>2、重复成交、越过有效权限 | 阻断并核对账本；不继续生成普通新买 |
| 每日 | 10%/15%/20%回撤触发、被困敞口、两只相关性 | 按冻结规则降仓/停用，记录实际未成交风险 |
| 每周 | 推荐与回填差异、未成交原因、价差与滑点 | 判断是否是执行假设失配，必要时降低信任等级 |
| 每月 | 因子分布、机会漏斗、行业集中、0/1/2持仓时间 | 检查数据口径与行情变化，先解释再登记研究 |
| 每季度 | 累计样本、分状态收益、候选相对主版的配对差异 | 形成保持/研究修订/退役决策，不强制改版 |

执行偏差初值：最近20笔可比成交的中位不利偏差超过模型滑点2倍，触发复核与暂停新增建议。
不足20笔则仅展示不确定性；人工临时改价导致的偏差与系统成交模型误差分开统计。
因子漂移初值：非重叠20日块的中位数连续3块超出训练期同类块的5%～95%范围，触发研究告警。
漂移本身不自动交易或换版；可比训练块不足20个时不使用该阈值，标记样本不足。
严重亏损由账户风控处理；短期收益排名、单月胜率和单笔失败不直接决定升级。

持续调优每半年、满足新增数据门槛后按 tuning.md 执行；季度复核本身不自动触发再搜索。
账户情景、参数选择政策与生产生效版本分开，不能用某个资金情景的最佳参数替代全部账户。

## 6. 数据与工程怎样演进

V0：全市场月排名与每日宽度按日批处理，量化后端保存小型结果和可复现快照。
V1：回测异步、单并发起步、可取消和进度可查；采集与查询优先，资源上限按现有运维规范。
日批发布从基础版即建设，优先于长研究任务；前台只返回快照，无结果不降级成即时重算。
V2：指标按依赖计算并复用，按数据版本失效缓存，禁止仅按日期命中后来修订的数据。
V3：事件和慢发布因子增量计算，业务日期与可用时间分离；每个推荐能还原其原始输入。
V4：财务与行业新增历史版本链；LLM提供有出处的解释，数值和股数仍由确定性计算产生。
V5：监测快照与推荐读取目标P95<500ms，记录机器、数据量与并发条件；慢回测不占同步请求。

接口扩展先改shared/contracts；MCP和前端只读后端结果，不直接访问量化库或自行重算交易数量。
不预设更换数据库或拆微服务；只有剖析证明现有边界无法满足需求，才单独提出架构方案。
