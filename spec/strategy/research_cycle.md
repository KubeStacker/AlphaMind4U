## 1. 每轮固定流程

`登记假设 → 核验数据/执行 → 提交后台任务 → 等待完成 → 校验产物 → 归因 → 决定唯一下一步`

任务状态为已登记、已排队、运行中、完成、失败、取消、阻断；“结果有效”是完成后的独立判定。
提交返回task_id只证明收到任务，不能写成已经回测；没有接口时先交工程缺口，不虚构请求地址。
读取已有task/run、刷新图表或导出仅取结果；计算只由提交研究任务或固定日批触发。
同一快照/配置重复提交去重，重试不能更换数据；修复输入后产生新run并保留原失败记录。
必要ETL与日批优先，研究低优先级，单并发起步；等待不占用同步查询线程。

| 任务/优先级 | 工作内容 | 前置 | 可审查交付 |
|---|---|---|---|

| M02/P0 | 固定S0/S1/S2/F1同账户对照 | 相应数据、账本与运行能力通过 | 全部基础结果、随机参考、逐笔和失败归因 |
| M03/P1 | 根据M02选择一次改善实验 | 已定位主要瓶颈 | 父版/候选共同区间对照、增量及代价 |
| M04/P1 | 一个家族的一张3×3表 | 家族已在开发数据冻结 | 全部9格、稳定邻域、选择政策与不更新理由 |

M01不等待复杂情绪/财务全齐；量价研究与增强数据分别列可信范围，不伪造共同历史。
M02仍属于experiments.md首轮8个固定版本的分批执行，另外4个按数据/实现状态标未运行。
首轮分支之外的排序、目标锁定或新因子不自动加入；另立假设并累计研究次数。
M06技术观察可先开始；它不能替代M05研究证据，也不必等全部增强实验做完。

## 4. 一张可提交的任务单

以下字段是任务信息要求，不是宣称当前API已经支持；实现者先落契约并回报可用入口。

| 字段 | 本目标默认/必填要求 |
|---|---|
| 任务身份 | campaign_id、task_id、parent_run、假设、唯一改动、提交人/时间 |
| 阶段 | technical/development/validation/holdout/shadow，记录此前是否访问过结果 |
| 账户 | C0=500000、最多2只、无外部入金/杠杆；完整account快照及hash |
| 额度/风险 | 默认总80%、单股40%、单股计划风险1%、合计2%、回撤10/15/20；不进入寻优 |
| 目标 | 同一账本分别保存期末>65万/≥100万、首次触及、风险内达成、可变现/已实现余额 |
| 股票池 | 全A前一完整自然月累计成交额Top20；历史版本、资格和权限冻结 |
| 时间与来源 | M00给出的可信范围、预热、正式日历、22:00截点、source/data/规则/费用版本 |
| 策略与执行 | 固定版本和全部参数、代码摘要、条件数量模型、滑点/延迟情景；禁止隐式默认 |
| 比较设计 | 父版、可执行S0、共同样本、开发/验证/终测边界、统计分组和选择政策 |
| 预算 | 参数×账户×窗口×压力及基准总数、固定种子、并发、截止/取消规则 |
| 输出 | run目录、全量明细、结果hash、失败原因、访问记录与复审结论 |

首轮只用50万默认情景；用户其他本金/额度另建任务并重演股数与现金，不按比例放大旧结果。
展示年度沿用validation.md已登记窗口；其他起点必须在读结果前登记，不按行情好坏挑起点。
所需数据不足时保持明确阻断，不能偷偷改成更容易盈利的短区间。

## 5. 首批预算实例与必交产物

以下35项保留为单窗口算例；本轮含四折、9格及年度起点的完整计划为167计算块，详见annual_campaign。
开发窗口确定后，基础4版×1账户×1窗口×1执行情景=4个账户run；随机两只20种子=20个run。
加现金/指数/Top20理论等权3项诊断、4版各两项独立压力8个run，合计35项，均登记结果。
两项压力为佣金与滑点翻倍、买入延迟一日；法定费率按真实日期，不将法定税费作为调参。
该35项只是一块开发数据的算例，不包含外层窗口、年度起点和后续调优，均须另计预算。
默认总子任务≤200；资源分批可行，但不能因此重置累计试验数或只跑被看好的参数。
9参数若跨3内部块、4外层折和3情景已达324项，提交前必须拆计划并完整保留所有必要格点。
这里块是计算子任务，账户延续规则仍按tuning执行；切块不能重置持仓、现金、冷却或回撤。

| 产物 | 必含内容 |
|---|---|
| manifest/quality | 完整冻结配置、来源版本、范围、缺失与适用性，不仅保存不能还原数据的hash |
| task/run清单 | 每个计划任务的实际ID、状态、耗时、失败、重试/缓存情况 |
| daily/equity | 逐日现金、持股、净资产、费用、真实/允许仓位、风险状态和被困敞口 |
| intents/fills/cycles | 首次信号、理由、冻结价量、成交或拒绝、完整持仓周期与未完成周期 |
| funnel/factors | 机会、金额、名额占用、因子覆盖及预登记条件表现 |
| comparisons/windows | 父子增量、胜率/盈亏比/净R、压力、年度目标及失败窗口 |
| review | 有效性、瓶颈、唯一建议、采用/保留/拒绝/证据不足、下一任务 |

推荐每个run使用独立产物目录，报告与清单互相链接；格式由实施者契约定义，不要求复制完整行情到Markdown。
必须同时可看简要报告和可核对明细；仅一张净值图或一张最佳参数截图不算回测交付。

## 6. 分析后的行动规则

1. 先判无效：未来信息、假成交、错池、漏费、负现金、第三只持仓，直接撤销绩效资格并回交修复。
2. 再判样本不足：缺完整周期/独立时间块/新行情，记录不足，继续数据或影子观察。
3. 再找瓶颈：分别比较净R、交易数、仓位、持有时长、共同亏损，选贡献最大的一个问题。
4. 只登记一个改动及代价，按win_rate_validation复验；没有增量时保留原版，不强制升级。
5. 家族确定后才用tuning的9格；优先稳定区域与验证增长，不能按最高胜率或一次翻倍排名。
6. 终测用来评估冻结政策；读完后形成的新假设只能在开发材料或后续新行情验证。

每周查数据/执行，每月整理失败归因，每季度评估是否需要新研究；不因此自动调参。
沿用每半年且至少新增100个交易日才再开局部搜索；紧急正确性修复另算，原错误绩效作废。
反复选最好结果会产生回测过拟合，保留失败尝试和访问谱系是持续优化的组成部分。[原始研究][pbo]

## 7. 何时算进展，何时算目标完成

| 结果 | 可以宣称 | 不能宣称 |
|---|---|---|
| 代码/账本/任务通过 | 技术可回放、可复核 | 有收益优势或已达到目标 |
| 有稳定成本后样本外增量 | 值得继续研究/进入规定观察 | 保证下一年翻倍 |
| 某历史一年从50万到65万以上/100万 | 该窗口对应30%/100%目标达成，注明是否风险内 | 已确定未来成功概率 |
| 冻结后实际账户一年内达标 | 该账户记录达成，注明估值/变现与成本 | 可以在任何下一年重复 |
| 9格无增益、样本不足或约束冲突 | 本批结束、目标未验证、等待新证据 | 为完成任务伪造收敛或继续无限搜参数 |

目标保留到可核验证据出现；不能承诺任何市场状态下一定找到满足约束的一年翻倍策略。
