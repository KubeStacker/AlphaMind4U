## 1. 阶段路线

| 阶段 | 优先级/估计 | 交付物 | 进入下一阶段的门槛 |
|---|---|---|---|
| G0 数据可靠性 | P0 / 3～5 工作日 | 已有修复复核、数据审计、交易规则清单 | 核心数据完整性可解释，任务失败不冒充成功 |
| G1 股票池与基线 | P0 / 3～5 工作日 | 月度Top20、可配置账户/两只账本、S0基准 | 历史名单可复算；成本、整手、未成交对账通过 |
| G2 最小策略 | P1 / 5～8 工作日 | S1/S2/F1日批结果、因子诊断、两只风控与机会漏斗 | 发布可复现、读取不重算；通过研究门槛 |
| G3 增强研究 | P1 / 5～8 工作日，补数另估 | E1/E2/E3、S3对照、归因、压力报告 | 共同样本内确有增益；不通过则保留 S1/S2 |
| G4 模拟推荐 | P2 / 3～5 工作日建设，加至少20交易日观察 | 已发布计划的持续影子、回填、偏差与采用记录 | 运行及执行无未解决阻断问题 |
| G5 基本面与事件 | P3 / 另估 | 财报版本、公告证据、行业与事件增强 | 历史时点数据可靠且带来独立增益 |

G0 → G1 → G2 为最先完成的主路径；G3 不通过不阻塞已通过验收的简单版本进入 G4。
当前先关闭[实现审查](implementation_review.md)的账本/风控阻断，再完成账户情景与年度回放。
具体执行清单和验收依赖见[next_steps.md](next_steps.md)，从T01开始；本页保留G阶段总体门槛。
本轮回测优先级：参数化账户与逐日账本 → 基础对照与逐笔回放 → 有限调优/情景比较 → 候选模拟。
完整演进、版本采用与退役见 [evolution.md](evolution.md)，主决策入口见 [plan.md](plan.md)。
G5 不抢占前三阶段资源；不优先建设自动交易、复杂机器学习、分钟全市场库或新微服务。

## 2. 第一张实施任务：G0

建议任务名：`Top20 策略数据就绪与采集正确性`。

- 先改 quant 对应 spec；涉及任务状态/质量输出时先改 shared/contracts，再编写 PLAN。
- 复核活动任务去重与终态重入队，复用 ops/drills.md 的已通过证据，仅修复仍失败路径。
- 复核子任务失败、额度、延迟发布和部分写入；已有修复不重复实施。
- 全市场行情审计：历史上市范围、退市、证券代码变更、停牌、复权因子、金额单位与去重。
- 核验交易日历与沪深北覆盖；明确缺失能否影响月度 Top20 排名。
- 设计历史ST、涨跌停价、公司行动、历史费用与交易规则来源，确认访问权限及回补成本。
- 质量汇总落快照，记录数据水位，避免每次查看全库扫描；参见 data.md 的架构边界。

验收证据：活动任务并发去重、完成后重跑、远端失败、延迟发布、重启恢复的结果。
另交付“可回测日期范围与不可用字段”清单，不把库大小当成可回测质量证明。

## 3. G1/G2 的具体交付

- 按 universe.md 逐月生成原始 Top20、过滤原因、可用时间及快照版本。
- 按account.md先设计账户情景契约，按execution.md支持现金、股数、费用、公司行动及两只限制。
- 同时生成Top20理论等权、目标账户S0和同约束随机参考，人工核验最小交易与换股样本。
- 实现 signals.md 定义的最少指标与 S1/S2，参数使用明确版本，不读取后续修订值。
- 批量回测分段执行并限制资源；提供取消、失败原因和进度，避免阻塞采集与查询。
- T05/T06先建设定时日批、完整输入冻结和结果发布，页面/MCP只读；夜批优先于长研究任务。
- 性能与策略增益分开评估，分层增量和日批/回测共核按[compute_quality.md](compute_quality.md)验收。
- 按 factors.md 计算首轮因子与缺失标记；按 factor_validation.md 检验Top20内前两名的选择增益。
- 优先核验1%风险下的机会和资金漏斗，再对照增强方案；parameters.md作为配置登记依据。
- 输出过去一年目标账户轨迹、多窗口验证、现金占比、回撤和失败情景。

建议交付顺序：可重建的池子 → 可对账的账本 → 基准净值 → 策略净值 → 归因和压力测试。
目标是先回答“同样的池子和执行约束下，策略增加了什么”，再决定是否引入更多因子。

## 4. G3/G4 的具体交付

- 接入情绪数据前登记口径、发布时间和缺失策略，按板块区分涨跌停制度。
- 每次只加入一个情绪维度，与基础策略在共同可用样本对照，记录失败实验。
- 按visualization.md展示配置/结果绑定、净值-回撤-仓位联动、参数格点、机会与资金漏斗和回放。
- 按tuning.md登记9组局部空间、数据访问和累计试验数；资源预估、取消、缓存、失败状态纳入契约。
- MCP 增加受控研究结果读取能力，所有计算仍在 quant；不得让模型直接拼库查询。
- 推荐记录标明策略版本、数据快照和有效执行窗口；模拟中记录忽略、拒单和追价取消。
- 每周复核数据水位、信号变化与执行偏差；改规则另开版本，原版轨迹保留。

G4结束交付继续模拟、退回修正或停止报告；不能自动切换实盘。
候选与当前版本分开模拟；实际采用只允许一个账户组合、最多两只，接管与回退遵守 evolution.md。

## 5. 工程验收

- 实施遵循 [SDD](../sdd.md)：spec → contract → plan → implement → verify。
- 已有月池迁移及回测接口，尚未覆盖全部规划；后续新增表和响应仍须迁移、完整契约与一致性测试。
- 测试重点：月末边界、历史退市、源数据修订、T+1、涨跌停、停牌、费用、重启及拒单。
- 新 SQL 附 EXPLAIN；分开记录锁等待与执行时间；按现有资源红线验收。
- 性能研究目标：质量/推荐快照读取 P95 < 500ms；在目标机器记录数据规模和并发条件。
- 后端检查与涉前端构建按现行 DoD 执行；仅文档计划阶段检查链接、索引和口径一致性。

## 6. 决策节点

开始历史实验前冻结实验预算和版本，核实可用历史；风险初值见 README.md。
进入账户模拟前确认板块权限、真实费用和可接受回撤；研究默认值不等于用户已同意。
一年翻倍只有在成本后轨迹中实际达到才标记达标；未达到如实记录，不据此放宽风险规则。

## 7. 工期与演进节奏

数据权限和历史质量满足时，前约1～2周完成G0/G1，第3～4周争取形成基础对照与问题清单。
随后至少4周覆盖20个交易日的执行模拟；行业/情绪增强可并行做独立研究，不阻断简单版本。
历史回补、真实预期或财务版本治理可能显著延长工期，不能以日历到期代替阶段验收。
每周核对运行与执行、每月整理改善证据、每季度做版本保留/升级/退役复核，具体见 evolution.md。
改善按 [improvement.md](improvement.md) 的问题模板登记，一轮有限实验后必须形成结论。
