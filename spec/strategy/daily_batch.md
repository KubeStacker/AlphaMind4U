# daily_batch — 每日提前计算与结果发布

> 历史参考：当前方案与待办已合并至[策略研究与实施方案](plan.md)。下文保留原日期记录；“方案被替代”不代表功能已验收。

> 2026-09-08用户确认：每天提前计算策略结果，查询时不实时计算。
> 状态：目标已确认，日批与发布能力待实施；本文不代表已部署定时任务或策略已通过验收。

实施中的研究队列先冻结完整回放输入，再计算并保存结果；POST只入队，GET仅读任务及已有结果。
输入快照包含日历、原始量价、月池内容、账户与参数；同版本中断恢复使用原快照；终态重新提交属于新实验，仍会准备当时的数据。
日批截止与真实账户延续仍需单独验收，研究输入冻结不能冒充22:00准时快照。

## 1. 产品目标与边界

主路径：`盘后数据就绪 → 固定截止快照 → 日批计算 → 校验并发布 → 页面/MCP只读结果`。
沿用quant-backend唯一量化库进程，不增加共享数据库的计算服务；架构边界见[architecture](../architecture.md)。
定时器只入队，任务在quant内部运行；打开页面、刷新、查询、解释、导出均不得调用策略重算。
没有已发布结果时返回待计算、阻断或失败及原因，禁止在GET或缓存未命中时同步补算。
人工历史回测和调优也进入后台研究队列；自由设置资金不等于在请求线程里立即重演账户。

每天计算与每天买入分开：S0按月，S1/S2仍按规定周末/月末评估新买，F1才每日评估新买。
每天均更新市场观察、持仓/风险和报告；非入场日、无信号、空仓也必须有明确结果。
每日用已冻结的策略参数计算；策略研究、重新选参和版本采用按[tuning](tuning.md)与[evolution](evolution.md)执行。

## 2. 默认批次时钟

时区Asia/Shanghai；22:00沿用parameters.md的数据截止，23:00是拟定发布目标，均非现役调度声明。
源数据就绪以[发布日历](../backend/quant/publish.md)及质量证据为准，定时触发成功不等于数据齐备。

| 时点 | 行为 | 产物 |
|---|---|---|
| 现有盘后采集及兜底之后 | 日批依赖就绪检查；预备计算只作临时结果 | 覆盖、缺口、任务/来源状态 |
| 交易日22:00 | 固定数据、账户、规则、策略及有效月池版本 | 可重演输入manifest与批次键 |
| 截止后至发布目标前 | 完成特征、信号、组合和报告校验 | 待发布结果包 |
| 默认23:00前 | 原子发布完整结果，或发布阻断/失败状态 | 下一交易日计划及完整元数据 |
| 次日查看时 | 读取指定账户与策略的已发布快照 | 相同版本的结果、解释和导出 |

月末在全市场完整性通过后，为下一自然月生成并冻结Top20，跨月信号使用对应新池。
缺数或任务超时不得借用截止之后的数据冒充准时完成；截止内已固定的输入可幂等重试。
超过发布目标标记延迟；超过新买执行窗口后即使完成也只作历史结果，不追发已过期买入计划。
截止后修订用于后续批次或明确标记的研究重算，不覆盖已发布意图与采用记录。
非交易日不制造新行情或重复推进冷却天数；展示最近结果、休市状态与真实下一交易日。
首版不增加盘中重算或盘前重选；将来新增定时批次须独立截止/版本，并同步回测时钟。

## 3. 输入与分层计算

```mermaid
flowchart LR
  A[数据与账户就绪] --> B[冻结输入版本]
  B --> C[全市场公共特征]
  C --> D[有效月池与持仓信号]
  D --> E[账户组合与条件计划]
  E --> F[校验并原子发布]
  F --> G[页面与MCP只读]
```

公共层按数据/公式版本复用：全市场金额、宽度、指数趋势、滚动历史与月池。
证券层覆盖“当前Top20 ∪ 实际持仓 ∪ 未完成退出意图”，离池且受困的旧仓不能被漏算。
账户层使用实际已知现金、持股、可卖量、未完成意图、高水位与有效配置，不从目标本金重新起算。
未接真实账户时明确标模拟账户；实际持仓/成交回填不完整时，不输出已适配真实账户的新增数量。
一份公共特征可服务多个资金情景，每个情景的股数、费用、现金和名额仍须独立计算。
有限参数实验另入研究队列；不得让日批对全部家族、全部资金和全部历史每天重新寻优。

## 4. 每日结果包

以下为待定义契约字段，不是现有API已具备的字段。

| 层级 | 必须保存的结果 |
|---|---|
| 批次 | run_id、decision_date、cutoff_at、computed_at、published_at、valid_for_trade_date |
| 版本 | 数据manifest、月池、账户配置/状态、策略、公式、执行与费用规则版本 |
| 市场 | 指数趋势、宽度及分母、情绪可用性、市场状态、允许仓位及判定理由 |
| 股票 | 原始Top20、资格/缺失原因、关键指标、排序、触发/失效条件和观察价位 |
| 账户 | 当前与目标敞口、现金、风险预算、已占名额、绑定约束、未完成退出 |
| 计划 | 持有/新买/减仓/退出/空仓，证券、数量上限、价格条件、有效窗口、理由 |
| 解释 | 固定数值对应的说明、无机会原因、数据质量、模拟与真实账户标记 |

新增意图与未退出旧仓合计始终受最多两只约束；观察表可以包含20只。
新买计划只在冻结的下一交易日执行窗口有效；过期后留档，不能显示为仍有效的新买建议。
有效交易日按决策日与正式日历冻结，不随查看日期滚动；盘前查看当天计划，不能错标为再下一天。
未成交退出意图持续保留，其状态与新买计划有效期分开；“计划退出”不代表已释放现金或名额。
报告应明确当日没有新买的原因，不能把数据未知、禁止新增和行情无机会统一写成空仓获胜。

## 5. 提前结果与未知成交价

盘后可以确定名单、信号、退出线、预算及条件，不能确定次日真实开盘价、可成交性和实际成交数量。
批次输出条件化计划，不能把历史回测中的次日参考价带入当时可见的推荐结果。
固定数量方案应在批内按冻结合法价格区间的最不利买价、费用和组合预算确定数量上限。
区间外或资格/成交条件不满足则不执行原新买；不得在查看报告时即时换股、扩量或重新排名。
前台不计算股数；条件核对及真实成交回填属于计划执行记录，不产生新的盘中策略结果。
这种事前固定数量方案与旧开盘后缩量模型分开命名、冻结和回测；未验证不能沿用旧模型收益结论。
开盘跳空、受困仓与新增公告仍可能令计划不可执行；无实时策略能力时不宣称提供盘中止损保障。

## 6. 发布、版本与配置生效

先生成完整临时结果包，检查账户不变量、数据质量和版本一致性，再原子切换published指针。
查询必须绑定账户/策略/有效交易日与published版本；不混用新指标、旧持仓和另一配置的曲线。
保留旧结果供历史查询，新批失败展示当前失败及旧结果日期，不能把昨天成功结果标成今天已发布。
幂等键包含决策日、数据快照、账户状态/配置、策略和规则版本；相同键重试不重复记账或发布。
账户配置在截止前保存，按返回的effective_decision_date生效；截止后修改默认进入下一批。
现金/成交回填修改形成新账户状态版本；旧报告仍绑定原状态，不能因页面输入改变就变成新结果。
自由资金研究先保存情景、后台完成再看新结果，不穷举所有本金，也不按比例放大旧交易。
解释优先使用确定性模板；若用LLM，在批后生成并绑定结果hash，失败不阻断数值结果发布。

## 7. 日批验收

- 同一输入版本日批与历史逐日重演的特征/意图一致；参考成交在未来行情可用后单独核算。
- 正常、无信号、非评估日、缺数、晚到、跨月/休市、旧仓离池受困均有正确的结果状态。
- 查询、刷新和导出多次不增加计算作业；无快照时也不触发补算；只记录允许的读取审计。
- 重复触发、失败重试、发布中查询及重启不产生重复交易、半包结果或错误配置生效。
- 日批不被研究任务长期占用资源，时限/内存/锁等待和来源水位可观测；指标见[compute_quality](compute_quality.md)。
